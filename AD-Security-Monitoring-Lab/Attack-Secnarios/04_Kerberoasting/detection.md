# Kerberoasting — Detection

## Overview

Detects abuse of Kerberos service ticket requests for offline password cracking. Any authenticated user can request a TGS for an SPN-registered account; the ticket is encrypted with that account's password hash and crackable offline. No failed logons, no admin rights, no obvious errors only normal-looking Kerberos traffic.

## MITRE ATT&CK (TTPs)

| Tactic            | Technique                                      | ID        |
| ----------------- | ---------------------------------------------- | --------- |
| Credential Access | Steal or Forge Kerberos Tickets: Kerberoasting | T1558.003 |

## Event IDs

| Event ID | Description                             |
| -------- | --------------------------------------- |
| 4769     | A Kerberos service ticket was requested |

## Detection Queries

### Targeted hunt — RC4-encrypted TGS requests

```spl
index=* EventCode=4769 Ticket_Encryption_Type=0x17
| table _time, Account_Name, Service_Name, Client_Address
| sort -_time
```

### Reduce noise — exclude machine accounts

```spl
index=* EventCode=4769 Ticket_Encryption_Type=0x17 Account_Name!="*$"
| table _time, Account_Name, Service_Name, Client_Address
| sort -_time
```

## Key Indicators (IOCs)

- `Ticket_Encryption_Type=0x17` (RC4-HMAC) is the primary IOC. Modern AD issues AES (`0x12`) by default. RC4 TGS requests targeting user-style accounts are the Kerberoasting fingerprint.
- Multiple TGS requests in quick succession from a single source.
- The requesting account differs from the service account being requested.
- A user account requesting tickets for SPN-enabled service accounts it has no business interacting with.

## Notes

- 4769 is high-volume on a normal DC (this lab had 160 in a short window from routine activity). Filtering by encryption type is what makes the hunt practical.
- `Account_Name!="*$"` strips machine accounts, which generate large amounts of legitimate Kerberos traffic.
- No failed logons are generated by Kerberoasting. The cracking step happens offline and produces no further DC events.
- Mitigation: strong service-account passwords (or gMSAs) defeat the attack even when the ticket is captured. The captured hash is only useful if it's crackable.
